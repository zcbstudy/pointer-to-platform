RoadToEmbedded
demo20_fork 学习笔记

一、核心目标

理解 Linux 中：
1. fork() 如何创建子进程
2. 为什么一次调用会出现两个返回结果
3. 父进程和子进程如何区分
4. 并发如何产生
5. 为什么父子进程可以执行不同任务


二、fork() 的作用

手册说明：

fork - create a child process

含义：

fork() 创建一个新的子进程。

调用前：

只有原来的父进程。

调用成功后：

1. 原来的父进程继续存在
2. 新增一个子进程
3. 父子进程都从 fork() 返回的位置继续执行

可以理解为：

原进程
   |
 fork()
   |
   +------ 父进程继续
   |
   +------ 子进程继续

注意：

源码中并没有真的出现两个 main()。

准确说法是：

同一份 main() 代码，
被父进程和子进程分别继续执行。


三、函数原型

pid_t fork(void);

需要头文件：

#include <sys/types.h>
#include <unistd.h>

pid_t：

专门用于表示进程 ID 的整数类型。


四、fork() 返回值

pid_t child_pid;

child_pid = fork();

返回值含义：

child_pid < 0

fork() 失败，没有创建子进程。


child_pid == 0

当前执行的是子进程。


child_pid > 0

当前执行的是父进程。

此时返回值是新创建子进程的 PID。


五、为什么一次调用会有两个返回结果

不是同一个进程连续得到两个返回值。

而是：

父进程中的 fork() 返回一次：
返回值是子进程 PID，大于 0。

子进程中的 fork() 返回一次：
返回值是 0。

即：

原父进程执行到 fork()
          |
          v
内核创建一个子进程
          |
          +---- 父进程：child_pid = 子进程 PID
          |
          +---- 子进程：child_pid = 0


六、为什么会产生并发

fork() 调用前只有一个执行流。

fork() 成功后，系统中有：

1. 父进程
2. 子进程

它们都是可以被 Linux 调度器独立调度的进程。

单核 CPU：

父进程和子进程交替运行，
形成并发。

多核 CPU：

父进程和子进程可能同时在不同核心运行，
形成并行。

所以：

fork() 调用一次
-> 新增一个子进程
-> 出现两个独立执行流
-> 内核分别调度
-> 产生并发


七、为什么父子进程可以做不同任务

fork() 后，父子进程都会继续执行后面的代码。

如果后面没有分支，它们会执行相同代码。

例如：

printf("hello\n");

父子进程都会执行一次，
所以可能打印两次。

通过 fork() 返回值，可以让它们进入不同分支：

if (child_pid < 0)
{
    // 创建失败
}
else if (child_pid == 0)
{
    // 子进程任务
}
else
{
    // 父进程任务
}

因此，一个 main() 可以组织两个不同的并发任务。


八、父子进程并不完全相同

fork() 刚成功时：

父子进程的代码和数据看起来几乎相同。

但它们至少有这些区别：

1. fork() 返回值不同
2. PID 不同
3. 是两个独立进程
4. 调度顺序不确定
5. 普通变量之后互不影响

例如：

int number = 10;

fork() 后，父子进程一开始都看到 number == 10。

之后：

子进程把 number 改成 20。
父进程把 number 改成 30。

最终：

子进程中的 number == 20。
父进程中的 number == 30。

它们不会互相直接修改对方的普通变量。


九、perror() 与 fork()

fork() 失败时可以使用 perror()：

child_pid = fork();

if (child_pid < 0)
{
    perror("fork");
    return 1;
}

注意：

perror("fork") 只能放在确认 fork() 失败的分支中。


十、demo20 最小代码

#include <sys/types.h>
#include <unistd.h>
#include <stdio.h>

int main(void)
{
    pid_t child_pid;

    child_pid = fork();

    if (child_pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (child_pid == 0)
    {
        printf("child process\n");
    }
    else
    {
        printf("parent process, child pid = %d\n",
               (int)child_pid);
    }

    return 0;
}


十一、编译

源文件应使用 .c 后缀，例如：

demo20_file_fork.c

编译：

gcc -Wall -Wextra -std=c11 demo20_file_fork.c -o demo20

运行：

./demo20

如果源文件没有 .c 后缀，GCC 可能无法把它识别为 C 源文件，
并把它交给链接器处理，从而出现：

file format not recognized
treating as linker script
syntax error


十二、本次实际运行结果

parent process, child pid = 9258
child process

说明：

1. fork() 创建成功
2. 父进程拿到子进程 PID：9258
3. 子进程进入 child_pid == 0 分支
4. 父子进程都执行了各自分支

这一次父进程先打印，子进程后打印。

但不能据此认为父进程永远先运行。

Linux 的调度顺序不确定，
下次运行也可能先看到子进程输出。


十三、demo20 核心结论

1. fork() 调用一次，会创建一个子进程。
2. 原来的父进程不会消失。
3. fork() 成功后，父子进程都从 fork() 后继续执行。
4. 父进程看到返回值大于 0。
5. 子进程看到返回值等于 0。
6. 返回值小于 0 表示创建失败。
7. 父子进程通过返回值进入不同分支。
8. 父子进程是两个独立的可调度对象。
9. 两个进程的执行顺序不能由 printf 顺序保证。
10. 同一个 main() 可以组织两个并发任务。
