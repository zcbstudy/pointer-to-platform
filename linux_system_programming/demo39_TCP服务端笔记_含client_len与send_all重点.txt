============================================================
0. 本节主线
============================================================

socket()
→ 创建 TCP socket，得到监听 fd

准备 struct sockaddr_in
→ 填本机 IPv4 + port

bind()
→ 把 socket 和本机 IP/port 绑定

listen()
→ 进入监听状态

accept()
→ 从等待连接队列中取一个客户端
→ 返回新的 client_fd

recv()
→ 从 client_fd 收数据

send()
→ 通过 client_fd 发数据

close(client_fd)
→ 当前客户端连接结束

继续 accept()
→ 等下一个客户端

服务器整体停服：
close(sockfd)


============================================================
1. socket()
============================================================

典型：

int sockfd = socket(
    AF_INET,
    SOCK_STREAM,
    0
);

参数：

AF_INET
→ IPv4 地址族

SOCK_STREAM
→ 流式 socket

0
→ 让内核选择与前两项匹配的默认协议
→ AF_INET + SOCK_STREAM 下即 TCP


返回：

sockfd >= 0
→ 成功，得到 fd

-1
→ 失败


检查：

if (sockfd == -1)
{
    perror("socket");
    return 1;
}


注意：

socket()
只是：
创建通信 endpoint + 返回 fd

还没有：
bind
listen
accept


============================================================
2. struct sockaddr_in：IPv4 地址盒子
============================================================

典型：

struct sockaddr_in addr;

memset(
    &addr,
    0,
    sizeof(addr)
);

addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
addr.sin_addr.s_addr = htonl(INADDR_ANY);


可以先把 sockaddr_in 理解成：

IPv4 地址族
+
IP
+
端口


成员：

sin_family
→ 地址族

sin_port
→ 端口

sin_addr.s_addr
→ IPv4 地址


INADDR_ANY
→ 绑定本机所有 IPv4 地址
→ 语义上相当于 0.0.0.0


注意：

服务端 bind 到：

0.0.0.0:8080

并不是让客户端连接：

0.0.0.0:8080

客户端仍连接具体可达地址，例如：

127.0.0.1:8080
192.168.x.x:8080


============================================================
3. htons() / htonl()
============================================================

网络字节序：
big-endian


htons()

host to network short
→ 主机字节序 → 网络字节序
→ 16 bit
→ 常用于端口


典型：

addr.sin_port = htons(8080);


htonl()

host to network long
→ 主机字节序 → 网络字节序
→ 32 bit
→ 常用于 IPv4 地址值


典型：

addr.sin_addr.s_addr = htonl(INADDR_ANY);


反向：

ntohs()
ntohl()


============================================================
4. bind()
============================================================

典型：

if (bind(
        sockfd,
        (struct sockaddr *)&addr,
        sizeof(addr)
    ) == -1)
{
    perror("bind");
    close(sockfd);
    return 1;
}


三个参数：

sockfd
→ 哪个 socket

(struct sockaddr *)&addr
→ 本机地址信息放在哪里

sizeof(addr)
→ 这个地址结构体有多少字节


核心：

socket()
→ 创建端点

bind()
→ 告诉内核这个 socket 绑定在哪个本机 IP + port


为什么 cast：

当前变量是：

struct sockaddr_in

bind() 接口使用通用：

struct sockaddr *

所以：

(struct sockaddr *)&addr


============================================================
5. listen()
============================================================

典型：

if (listen(
        sockfd,
        5
    ) == -1)
{
    perror("listen");
}


作用：

把已经 bind 的 TCP socket
转成监听 socket


第二参数：

5
→ backlog


第一轮理解：

backlog
≈ 等待 accept 的连接队列长度请求


注意：

这个 5 不是：

客户端地址长度
5 个端口
最多只能存在 5 个 client_fd
整个服务器最多只能服务 5 个客户端


已经被 accept() 取出的连接：

→ 已离开等待 accept 的队列
→ 有自己的 client_fd


============================================================
6. accept()
============================================================

典型：

struct sockaddr_in client_addr;

socklen_t client_len =
    sizeof(client_addr);

int client_fd = accept(
    sockfd,
    (struct sockaddr *)&client_addr,
    &client_len
);


作用：

从监听 socket 的等待连接队列里
取出一个已经建立好的客户端连接

并返回：

一个新的 client_fd


----------------------------------------
6.1 三个参数
----------------------------------------

第 1 个：

sockfd

→ 从哪个监听 socket 的队列取连接


第 2 个：

(struct sockaddr *)&client_addr

→ 让内核把“客户端的 IP + port”等地址信息写到这里


第 3 个：

&client_len

→ 一个“输入 + 输出”参数


============================================================
【重点易错 1：client_len 到底是什么】
============================================================

先看：

struct sockaddr_in client_addr;

这只是声明了一块内存：

client_addr

用于存放：

客户端地址信息


然后：

socklen_t client_len =
    sizeof(client_addr);

这里：

sizeof(client_addr)

不是 backlog。

它表示：

client_addr 这个结构体
一共占多少字节


例如概念上：

client_addr
→ 一个地址信息缓冲区

client_len
→ 这块缓冲区的容量


调用 accept() 前：

client_len = sizeof(client_addr);

相当于程序告诉内核：

“我给你准备的 client_addr
最多有这么大的空间。”


所以：

accept(
    sockfd,
    (struct sockaddr *)&client_addr,
    &client_len
);


为什么是：

&client_len

而不是：

client_len

因为内核不只是“读取”这个长度，
还可能需要把实际地址长度写回 client_len。


所以它是：

输入：
告诉内核 client_addr 有多大

输出：
内核把实际使用的地址长度写回来


因此必须传：

&client_len

也就是：

把 client_len 变量自己的地址交给内核


类比：

int n = 10;

如果函数只需要知道 n：

func(n);

如果函数需要修改 n：

func(&n);


accept 的 client_len
属于第二种。


----------------------------------------
6.2 listen 的 5 和 client_len 完全不同
----------------------------------------

listen(sockfd, 5);

这里的 5：

→ backlog
→ 连接队列相关


accept(..., &client_len);

这里的 client_len：

→ 客户端地址结构体的字节长度


两者没有直接关系。


----------------------------------------
6.3 accept 返回的新 fd
----------------------------------------

例如：

sockfd = 3

它负责监听。


客户端 A：

accept(...)
→ client_fd = 4


客户端 B：

下一次 accept(...)
→ client_fd = 5


于是：

fd 3
→ 继续监听

fd 4
→ 和 A 通信

fd 5
→ 和 B 通信


client_fd：

是服务器本地内核分配的 fd

不是客户端把 fd 发给服务器。


----------------------------------------
6.4 不关心客户端地址
----------------------------------------

可以：

int client_fd = accept(
    sockfd,
    NULL,
    NULL
);

意思：

只要新连接 fd
不需要客户端 IP/port 信息。


============================================================
7. recv()
============================================================

典型：

char buf[128];

ssize_t n = recv(
    client_fd,
    buf,
    sizeof(buf) - 1,
    0
);


参数：

client_fd
→ 从哪个具体客户端连接收

buf
→ 数据放到哪里

sizeof(buf) - 1
→ 本次最多收多少字节

0
→ 默认 flags


返回：

n > 0
→ 这次实际收到 n 字节

n == 0
→ 对端正常关闭发送方向
→ 并且已有数据已经全部读完

n == -1
→ 出错


默认阻塞 socket：

如果当前只是暂时没数据：

recv()
→ 不返回
→ 等着


所以：

没数据
≠ recv 返回 0


recv 返回 0：

表示 TCP 字节流已经到头。


----------------------------------------
7.1 为什么 sizeof(buf) - 1
----------------------------------------

char buf[128];

数组下标：

0 ～ 127


如果：

recv(
    fd,
    buf,
    127,
    0
);

最多收到：

127 字节


这些网络数据占：

buf[0] ～ buf[126]


然后：

buf[127] = '\0';


正好不越界。


----------------------------------------
7.2 recv 不自动补 '\0'
----------------------------------------

假设收到：

hello

n = 5


内存只保证：

buf[0] = 'h'
buf[1] = 'e'
buf[2] = 'l'
buf[3] = 'l'
buf[4] = 'o'


不保证：

buf[5] = '\0'


所以当作 C 字符串使用时：

if (n > 0)
{
    buf[n] = '\0';
    printf("%s\n", buf);
}


如果处理二进制数据：

不要依赖 '\0'
直接用 n 作为有效长度。


----------------------------------------
7.3 recv 一次不保证拿完整逻辑消息
----------------------------------------

recv(fd, buf, 1000, 0);

1000：

→ 最大可接收长度

不是：

→ 一定返回 1000


可能：

第一次 recv → 200
第二次 recv → 500
第三次 recv → 300


TCP 是字节流：

一次 send
≠
一次 recv


============================================================
8. send()
============================================================

典型：

ssize_t n = send(
    client_fd,
    buf,
    len,
    0
);


参数：

client_fd
→ 通过哪条客户端连接发送

buf
→ 要发的数据

len
→ 请求发送多少字节

0
→ 默认 flags


返回：

n >= 0
→ 本次本机内核接受了多少字节用于发送

-1
→ 出错


注意：

send 返回 600

表示：

这一次本机内核接受了 600 字节


不表示：

对端已经 recv 到 600
对端程序已经处理 600
一个 TCP 包就是 600 字节


============================================================
【重点易错 2：为什么需要 send_all()】
============================================================

问题：

send() 不保证一次把 len 字节全部交给内核。


例如：

len = 1000

第一次：

send(
    fd,
    buf,
    1000,
    0
);

可能返回：

600


表示：

前 600 字节已经交给内核

还剩：

400 字节


所以程序必须继续：

从没发完的位置开始

再发送剩余长度。


这就是 send_all() 的作用。


============================================================
9. send_all() 逐行理解
============================================================

代码：

int send_all(
    int fd,
    const char *buf,
    int len
)
{
    int total = 0;

    while (total < len)
    {
        ssize_t n = send(
            fd,
            buf + total,
            len - total,
            0
        );

        if (n == -1)
        {
            perror("send");
            return -1;
        }

        total += n;
    }

    return total;
}


----------------------------------------
9.1 total
----------------------------------------

int total = 0;

表示：

到目前为止
一共成功交给内核多少字节


开始：

total = 0


----------------------------------------
9.2 while
----------------------------------------

while (total < len)

只要：

已经发送总量
<
目标总长度

就说明：

还有剩余数据没发完。


----------------------------------------
9.3 buf + total
----------------------------------------

这是整个 send_all 最关键的一句。


buf：

原始数据起点


total：

前面已经成功发送多少字节


所以：

buf + total

表示：

从“还没发送的第一个字节”开始


例：

buf 有 1000 字节

第一次 send 返回 600

total = 600


第二次：

buf + total
=
buf + 600

表示：

从第 600 个偏移开始继续发


也就是：

跳过前面已经发送成功的 600 字节。


----------------------------------------
9.4 len - total
----------------------------------------

len：

总共要发多少


total：

已经发多少


所以：

len - total

就是：

还剩多少字节


例：

len = 1000
total = 600


剩余：

1000 - 600
=
400


于是第二次调用：

send(
    fd,
    buf + 600,
    400,
    0
);


意思：

从 buf 后移 600 字节的位置开始

再请求发送剩余 400 字节。


----------------------------------------
9.5 完整数字例子
----------------------------------------

目标：

len = 1000


开始：

total = 0


第一次：

send(
    fd,
    buf + 0,
    1000 - 0,
    0
);

假设返回：

600


于是：

total = 600


第二次：

send(
    fd,
    buf + 600,
    1000 - 600,
    0
);

即：

send(
    fd,
    buf + 600,
    400,
    0
);

假设返回：

300


于是：

total = 900


第三次：

send(
    fd,
    buf + 900,
    100,
    0
);

假设返回：

100


于是：

total = 1000


判断：

while (1000 < 1000)

为假


循环结束。


一句话记忆：

send_all():

total
→ 已发送多少

buf + total
→ 从哪里继续

len - total
→ 还剩多少

============================================================
11. TCP FIN 与 recv == 0
============================================================

TCP 是全双工：

A → B

B → A

两个方向可以分别结束。


当一端：

close(socket)

或者：

shutdown(SHUT_WR)

内核 TCP 状态机会关闭自己的发送方向。


通常：

→ 发送 FIN


接收端：

如果 FIN 前还有没读完的数据

recv()
→ 先继续把已有数据交给程序


数据全部读完后：

recv()
→ 0


所以：

recv == 0

不是：

“暂时没数据”

而是：

对端发送方向正常结束
+
之前的数据已经读完。


============================================================
12. sockfd 和 client_fd 的生命周期
============================================================

sockfd：

监听 fd

负责：

accept 新连接


client_fd：

某一个客户端的已连接 fd

负责：

recv/send


当前客户端结束：

close(client_fd);


然后：

回到 accept()
继续等新客户端


服务器整体不再接新连接：

close(sockfd);


注意：

close(sockfd)

只表示：

“关门，不接新客”


不会自动：

close 所有已经存在的 client_fd


已有连接：

仍然可以继续 recv/send。


以后做优雅停服：

1. 停止 accept 新连接
2. 已有 client_fd 继续工作
3. 客户端逐个结束
4. close 各 client_fd
5. 活跃连接数归 0
6. 服务器退出


如果多线程维护：

client_count++
client_count--

这是共享可写数据

→ 以后要用 mutex / atomic 等同步。

13. demo39 完整骨架
============================================================

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>


int main(void)
{
    int sockfd = socket(
        AF_INET,
        SOCK_STREAM,
        0
    );

    if (sockfd == -1)
    {
        perror("socket");
        return 1;
    }


    struct sockaddr_in addr;

    memset(
        &addr,
        0,
        sizeof(addr)
    );

    addr.sin_family = AF_INET;
    addr.sin_port = htons(8080);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);


    if (bind(
            sockfd,
            (struct sockaddr *)&addr,
            sizeof(addr)
        ) == -1)
    {
        perror("bind");
        close(sockfd);
        return 1;
    }


    if (listen(sockfd, 5) == -1)
    {
        perror("listen");
        close(sockfd);
        return 1;
    }


    while (1)
    {
        struct sockaddr_in client_addr;

        socklen_t client_len =
            sizeof(client_addr);

        int client_fd = accept(
            sockfd,
            (struct sockaddr *)&client_addr,
            &client_len
        );

        if (client_fd == -1)
        {
            perror("accept");
            continue;
        }


        while (1)
        {
            char buf[128];

            ssize_t n = recv(
                client_fd,
                buf,
                sizeof(buf) - 1,
                0
            );

            if (n > 0)
            {
                buf[n] = '\0';

                printf(
                    "recv: %s\n",
                    buf
                );
            }
            else if (n == 0)
            {
                break;
            }
            else
            {
                perror("recv");
                break;
            }
        }


        close(client_fd);
    }


    close(sockfd);

    return 0;
}
