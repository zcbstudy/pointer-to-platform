1. gcc
======================================================================

分离编译：

gcc -Wall -Wextra -std=c11 -c main.c -o main.o
gcc -Wall -Wextra -std=c11 -c worker.c -o worker.o

链接：

gcc main.o worker.o -o app

运行：

./app


常用参数：

-Wall
→ 常见警告

-Wextra
→ 更多警告

-std=c11
→ 使用 C11

-c
→ 只编译，不链接

-o name
→ 指定输出文件名

pthread 程序常用：

gcc demo.c -o demo -pthread


======================================================================
2. Makefile
======================================================================

最小模板：

app: main.o worker.o
	gcc main.o worker.o -o app

main.o: main.c worker.h
	gcc -Wall -Wextra -std=c11 -c main.c -o main.o

worker.o: worker.c worker.h
	gcc -Wall -Wextra -std=c11 -c worker.c -o worker.o


核心格式：

target: dependencies
<Tab>command

注意：
命令前是真正的 Tab。

make：
→ 根据依赖与修改时间决定哪些目标需要重建。

======================================================================
3. open()
======================================================================

最简：

int fd = open(
    "a.txt",
    O_RDONLY
);

带创建：

int fd = open(
    "a.txt",
    O_WRONLY | O_CREAT | O_APPEND,
    0644
);


原型核心：

int open(
    const char *pathname,
    int flags,
    ...
);


参数：

pathname
→ 路径

flags
→ 打开方式

mode
→ 只有创建文件时才有意义


常见 flags：

O_RDONLY
→ 只读

O_WRONLY
→ 只写

O_RDWR
→ 读写

O_CREAT
→ 不存在则创建

O_TRUNC
→ 打开时截断为 0 长度

O_APPEND
→ 每次 write 写到文件末尾


返回：

fd >= 0
→ 成功

-1
→ 失败


典型检查：

if (fd == -1)
{
    perror("open");
    return 1;
}


======================================================================
4. write()
======================================================================

ssize_t n = write(
    fd,
    buf,
    count
);

例如：

ssize_t n = write(
    fd,
    "hello",
    5
);


参数：

fd
→ 写到哪个已打开资源

buf
→ 数据地址

count
→ 请求写多少字节


返回：

n >= 0
→ 实际写入字节数

-1
→ 失败


重要：

请求写 1000
不代表一定返回 1000。

可能出现 partial write。


======================================================================
5. read()
======================================================================

char buf[128];

ssize_t n = read(
    fd,
    buf,
    sizeof(buf)
);


参数：

fd
→ 从哪个资源读

buf
→ 数据放哪

sizeof(buf)
→ 本次最多读多少


返回：

n > 0
→ 实际读到 n 字节

n == 0
→ 对普通文件表示 EOF

n == -1
→ 失败


典型循环：

ssize_t n;

while ((n = read(
            fd,
            buf,
            sizeof(buf)
        )) > 0)
{
    /* 只使用 buf[0] ～ buf[n - 1] */
}

if (n == -1)
{
    perror("read");
}


关键：

sizeof(buf)
→ 最大容量

n
→ 本次真实数据长度


======================================================================
6. close()
======================================================================

if (close(fd) == -1)
{
    perror("close");
}


作用：

当前进程释放这个 fd。


返回：

0
→ 成功

-1
→ 失败

======================================================================
7. lseek()
======================================================================

头文件：

#include <unistd.h>


原型：

off_t lseek(
    int fd,
    off_t offset,
    int whence
);


典型：

lseek(fd, 0, SEEK_SET);
→ 文件开头

lseek(fd, 0, SEEK_CUR);
→ 当前偏移

lseek(fd, 0, SEEK_END);
→ 文件末尾

lseek(fd, 2, SEEK_CUR);
→ 当前位置后移 2

lseek(fd, -2, SEEK_CUR);
→ 当前位置前移 2


whence：

SEEK_SET
→ 相对文件开头

SEEK_CUR
→ 相对当前位置

SEEK_END
→ 相对文件末尾


返回：

成功
→ 新文件偏移量

-1
→ 失败


重要：

lseek
→ 改“文件偏移”

write
→ 默认覆盖
→ 不是中间插入

======================================================================
8. fd 模型
======================================================================

程序启动时通常：

0
→ STDIN_FILENO

1
→ STDOUT_FILENO

2
→ STDERR_FILENO


fd：

当前进程 fd 表中的整数索引。


不是：

文件本身
永久编号
跨进程通用编号


fd 可代表：

普通文件
终端
pipe
socket
设备


======================================================================
9. dup()
======================================================================

int newfd = dup(oldfd);


作用：

复制 oldfd 的引用
→ 返回一个新的 fd


典型：

int newfd = dup(fd);

if (newfd == -1)
{
    perror("dup");
}


返回：

>= 0
→ 新 fd

-1
→ 失败


内核通常选择：

当前进程可用的最小 fd。


======================================================================
10. dup2()
======================================================================

int ret = dup2(
    oldfd,
    newfd
);


作用：

让 newfd 指向 oldfd 所指资源。


典型重定向 stdout：

if (dup2(
        fd,
        STDOUT_FILENO
    ) == -1)
{
    perror("dup2");
}


pipe 场景：

dup2(
    pipefd[1],
    STDOUT_FILENO
);

→ 标准输出接到 pipe 写端


dup2(
    pipefd[0],
    STDIN_FILENO
);

→ 标准输入接到 pipe 读端


返回：

成功
→ newfd

失败
→ -1


======================================================================
11. errno / perror()
======================================================================

#include <stdio.h>
#include <errno.h>


系统调用失败常见：

返回 -1
+
设置 errno


perror：

perror("open");

输出概念：

open: No such file or directory


注意：

perror 只有在刚刚确定调用失败后使用。


正确：

if (fd == -1)
{
    perror("open");
}


不是：

open(...);
perror("open");


pthread 系列：
通常直接返回错误码
不能一律套 errno/perror。

12. fork()
======================================================================

#include <sys/types.h>
#include <unistd.h>


pid_t pid = fork();

if (pid == -1)
{
    perror("fork");
}
else if (pid == 0)
{
    /* child */
}
else
{
    /* parent */
}


返回：

-1
→ 创建失败

0
→ 当前执行流是子进程

>0
→ 当前执行流是父进程
→ 返回值是子 PID


核心：

调用一次 fork
→ 成功后有父子两个执行流
→ 都从 fork 后继续

======================================================================

WEXITSTATUS(status)
→ 正常退出码


注意：

正常退出
≠
一定成功

例如：

return 1;

仍然是：
正常退出机制

只是退出码为 1。

WTERMSIG

16. execl()
======================================================================

#include <unistd.h>


典型：

execl(
    "./worker",
    "worker",
    (char *)NULL
);


或：

execl(
    "/bin/ls",
    "ls",

exec
→ 不创建新进程
→ 用新程序替换当前进程程序映像


成功：

不返回原程序


失败：

返回 -1


典型：

if (fork() == 0)
{

        "./worker",

    perror("execl");

    return 1;
}


参数：

第 1 个
→ 可执行文件路径

后续
→ argv 参数

最后
→ NULL 结束

======================================================================
17. pipe()
======================================================================

#include <unistd.h>


int fd[2];

if (pipe(fd) == -1)
{
    perror("pipe");
}


产生：

fd[0]
→ 读端

fd[1]
→ 写端


数据链：

write(fd[1])
→ 内核 pipe buffer
→ read(fd[0])


所有写端都关闭后：

read(fd[0])
→ 最终返回 0


======================================================================
18. pipe + dup2 + exec 模板
======================================================================

假设：

程序 A 输出
→ pipe
→ 程序 B 输入


A 子进程：

close(fd[0]);

dup2(
    fd[1],
    STDOUT_FILENO
);

close(fd[1]);

execl(...);


B 子进程：

close(fd[1]);

dup2(
    fd[0],
    STDIN_FILENO
);

close(fd[0]);

execl(...);


父进程：

close(fd[0]);
close(fd[1]);

wait(NULL);
wait(NULL);


核心：

pipe
→ 建通道

dup2
→ 接线

exec
→ 换程序

======================================================================

作用：

20. signal()
======================================================================

#include <signal.h>


void handler(int sig)
{
    (void)sig;
}


if (signal(
        SIGTERM,
        handler
    ) == SIG_ERR)
{
    perror("signal");
}


作用：

给某 signal 登记处理函数。


返回：

成功
→ 原处理方式

失败
→ SIG_ERR


后面 demo34：
更推荐 sigaction。


======================================================================
21. waitpid()
======================================================================

#include <sys/wait.h>


int status;

pid_t ret = waitpid(
    child_pid,
    &status,
    0
);


参数：

child_pid
→ 等哪个子进程

&status
→ 内核写结束状态

0
→ 默认阻塞等待


返回：

>0
→ 被回收 PID

0
→ 某些 option（如 WNOHANG）时表示当前没有已结束目标

-1
→ 失败


WNOHANG：

pid_t ret = waitpid(
    child_pid,
    &status,
    WNOHANG
);


ret == 0
→ 当前子进程还没有结束
→ 本次不阻塞

22. demo26 标准 fork + exec + waitpid

if (child == -1)
{
    perror("fork");
    return 1;

if (child == 0)

else if (WIFSIGNALED(status))
{
    printf(

    );
}

pthread_mutex_unlock(

作用：

======================================================================
28. pthread_mutex_trylock()
======================================================================

#include <errno.h>


int ret = pthread_mutex_trylock(
    &mutex
);


ret == 0
→ 成功持锁

ret == EBUSY
→ 当前锁忙
→ 立即返回
→ 不阻塞


重要：

trylock 失败后：
这次函数调用已经结束。

它不会：
以后锁空了自动回来。

);

======================================================================
30. deadlock
======================================================================

经典：

A：
lock(a)
lock(b)

B：
lock(b)
lock(a)


可能：

A 持 a 等 b
B 持 b 等 a

→ deadlock


避免：

所有线程统一锁顺序：

a
→ b
→ c


忙等：

while (
    pthread_mutex_trylock(&mutex)
    != 0
)
{
}


→ 一直消耗 CPU
→ 通常不推荐

31. pthread_cond_init()

======================================================================
32. pthread_cond_wait()
======================================================================

典型：

pthread_mutex_lock(
    &mutex
);

while (ready == 0)
{
    pthread_cond_wait(
        &cond,
        &mutex
    );
}

/* 条件满足 */

pthread_mutex_unlock(
    &mutex
);


完整机制：

线程先持 mutex
→ 检查 ready
→ 条件不满足
→ cond_wait
→ 原子地释放 mutex + 睡眠
→ 被 signal/broadcast 唤醒
→ 重新竞争 mutex
→ 拿到 mutex
→ cond_wait 返回
→ while 再检查 ready


两个参数：

&cond
→ 睡在哪个条件变量

&mutex
→ wait 时释放、醒后重新获取哪把锁


为什么 while：

醒来
≠
条件一定仍然成立

所以：
必须重新检查真实条件。


======================================================================
33. pthread_cond_signal()
======================================================================

pthread_cond_signal(
    &cond
);


作用：

唤醒一个正在等待该 cond 的线程。


注意：

唤醒
≠
立即运行

唤醒后：
还要抢 mutex。


======================================================================
34. pthread_cond_broadcast()
======================================================================

pthread_cond_broadcast(
    &cond
);


作用：

唤醒所有等待该 cond 的线程。

之后：
所有线程继续竞争 mutex。


======================================================================
35. pthread_cond_destroy()
======================================================================

pthread_cond_destroy(
    &cond
);


销毁前：
不能再有线程使用 cond。


核心分工：

mutex
→ 保护共享状态

ready
→ 真正条件

cond
→ 等待/通知

95. accept(..., &client_len) 为什么有 &
======================================================================

accept 的第三参数：

它是：

输入 + 输出参数


调用前：

client_len =
    sizeof(client_addr);


程序告诉内核：

“我给你的 client_addr
最多有这么大的空间。”


调用后：

内核可以修改 client_len


告诉程序：

“实际客户端地址用了多少长度。”


所以必须传：

&client_len


因为：

只传 client_len
→ 内核只拿到数值副本
→ 不能写回变量


传 &client_len
→ 内核拿到变量地址
→ 可以更新它


这和：

属于同一类“输出参数”机制。

→ 对端发送方向正常结束
→ 已有数据也全部读完

n == -1
→ 错误


默认阻塞 socket：

当前只是没数据
→ recv 不返回
→ 原地等待


所以：

暂时没数据
≠ recv 返回 0


======================================================================
98. recv 与 '\0'
======================================================================

recv：

只收字节
不理解 C 字符串
不会自动补 '\0'


例如：

收到 hello

n = 5


只保证：

buf[0] = 'h'
buf[1] = 'e'
buf[2] = 'l'
buf[3] = 'l'
buf[4] = 'o'


如果要用：

printf("%s", buf);


必须：

buf[n] = '\0';


完整：

ssize_t n = recv(
    client_fd,
    buf,
    sizeof(buf) - 1,
    0
);

if (n > 0)
{
    buf[n] = '\0';

    printf(
        "%s\n",
        buf
    );
}


为什么减 1：

char buf[128]

数据最多收：

127 字节


有效数据：

buf[0] ～ buf[126]


最后：

buf[127] = '\0';


正好不越界。


二进制数据：

不要依赖 '\0'
直接按 n 处理。

可能：

≠

======================================================================
102. send_all()
======================================================================

这是我们自己写的辅助函数，
不是系统 API。


作用：

反复 send
直到把 len 字节全部交给内核，
或者发生错误。


第一轮版本：

int send_all(
    int fd,
    const char *buf,
    int len
)
{
    int total = 0;

    while (total < len)
    {
        ssize_t n = send(
            fd,
            buf + total,
            len - total,
            0
        );

        if (n == -1)
        {
            perror("send");
            return -1;
        }

        if (n == 0)
        {
            return total;
        }

        total += (int)n;
    }

    return total;
}


三个核心变量：

total
→ 已经发送多少

buf + total
→ 从哪里继续发送

len - total
→ 还剩多少


数字例：

len = 1000

total = 0


第一次：

send(
    fd,
    buf + 0,
    1000,
    0
);

返回：

600


total = 600


第二次：

send(
    fd,
    buf + 600,
    400,
    0
);

返回：

300


total = 900


第三次：

send(
    fd,
    buf + 900,
    100,
    0
);

返回：

100


total = 1000

while 条件：

1000 < 1000

false

结束。

======================================================================
104. TCP FIN / recv == 0
======================================================================

TCP 全双工：

A → B
B → A


每个方向可分别关闭。


一端：

close(socket)

或：

shutdown(SHUT_WR)


→ 内核关闭本端发送方向
→ TCP 通常发送 FIN


接收端：

如果 FIN 前还有数据没读：

recv
→ 先把已有数据交给程序


已有数据读完：

下一次 recv
→ 0


所以：

recv == 0
不是：
“暂时没有数据”

而是：
对端发送方向结束
+
现有数据已读完。


======================================================================
105. sockfd / client_fd 生命周期
======================================================================

sockfd
→ listening socket
→ 负责 accept 新连接


client_fd
→ 一个已连接客户端
→ 负责 recv/send


客户端结束：

close(client_fd);


然后：

继续 accept(sockfd, ...);


服务器整体停服：

close(sockfd);


重要：

close(sockfd)
→ 不再接新连接

不会自动：

关闭所有已 accept 的 client_fd


已有客户端：
可以继续通信。


以后优雅停服：

停止接新连接
→ 等已有 client_fd 结束
→ client_count 归 0
→ 进程退出


多线程环境：

client_count++
client_count--

属于共享可写数据
→ 需要 mutex / atomic 等同步。
