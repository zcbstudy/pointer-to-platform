============================================================
1. inet_ntop()
============================================================

作用：

把二进制形式的 IP 地址
转换成
人可以直接阅读的字符串 IP。

例如：

二进制 IPv4
→ "192.168.1.20"

典型场景：

服务端 accept() 后已经拿到：

struct sockaddr_in client_addr;

其中：

client_addr.sin_addr

里面就是客户端的二进制 IPv4 地址。

如果想打印客户端 IP：

char ip[INET_ADDRSTRLEN];

const char *ret = inet_ntop(
    AF_INET,
    &client_addr.sin_addr,
    ip,
    sizeof(ip)
);

if (ret == NULL)
{
    perror("inet_ntop");
}
else
{
    printf(
        "client ip: %s\n",
        ip
    );
}


============================================================
2. inet_ntop() 四个参数
============================================================

inet_ntop(
    AF_INET,
    &client_addr.sin_addr,
    ip,
    sizeof(ip)
);

第 1 个：

AF_INET
→ 当前转换 IPv4 地址

第 2 个：

&client_addr.sin_addr
→ 二进制 IP 在哪里

第 3 个：

ip
→ 转换后的字符串 IP 放哪里

第 4 个：

sizeof(ip)
→ ip 这个字符数组有多少空间


============================================================
3. inet_pton() 和 inet_ntop() 对照
============================================================

demo40：

inet_pton()

presentation
→ network

字符串 IP
→ 二进制 IP

例如：

"127.0.0.1"
→ inet_pton
→ server_addr.sin_addr


demo41：

inet_ntop()

network
→ presentation

二进制 IP
→ 字符串 IP

例如：

client_addr.sin_addr
→ inet_ntop
→ "192.168.1.20"

可以记：

pton
→ 人看的 → 网络格式

ntop
→ 网络格式 → 人看的


============================================================
4. INET_ADDRSTRLEN
============================================================

IPv4 字符串缓冲区常写：

char ip[INET_ADDRSTRLEN];

INET_ADDRSTRLEN：

→ 系统提供的 IPv4 文本地址缓冲区长度常量

第一轮不需要自己算：

"255.255.255.255"

到底多少字符。

直接用：

INET_ADDRSTRLEN


============================================================
5. inet_ntop() 返回值
============================================================

成功：

返回 dst
→ 也就是输出字符串地址

失败：

返回 NULL
→ 设置 errno

所以可以：

if (inet_ntop(
        AF_INET,
        &client_addr.sin_addr,
        ip,
        sizeof(ip)
    ) == NULL)
{
    perror("inet_ntop");
}


============================================================
6. shutdown()
============================================================

shutdown()：

不是直接销毁 fd。

它可以：

只关闭 TCP 的某一个通信方向。

典型：

shutdown(
    sockfd,
    SHUT_WR
);

含义：

关闭本端的发送方向。

之后：

不能再正常继续 send()

但：

还可以 recv()


============================================================
7. TCP 为什么可以只关一个方向
============================================================

TCP 是全双工：

A → B

和

B → A

是两个方向。

所以可以：

只关闭：

A → B

但保留：

B → A

这叫：

half-close
→ 半关闭


============================================================
8. shutdown() 两个参数
============================================================

shutdown(
    sockfd,
    SHUT_WR
);

第 1 个：

sockfd
→ 哪条已经建立的 socket 连接

第 2 个：

how
→ 关闭哪个方向

常见：

SHUT_RD
→ 关闭本端接收方向

SHUT_WR
→ 关闭本端发送方向

SHUT_RDWR
→ 收发两个方向都关闭


============================================================
9. 最重要的 SHUT_WR
============================================================

例如客户端：

send(
    sockfd,
    buf,
    len,
    0
);

数据已经全部发完。

然后：

shutdown(
    sockfd,
    SHUT_WR
);

含义：

“我不会再给你发新数据了。”

但客户端还可以：

recv(
    sockfd,
    buf,
    sizeof(buf),
    0
);

继续等服务器回复。

典型模型：

客户端：
发送请求
→ shutdown(SHUT_WR)
→ 继续 recv

服务器：
recv
→ 最终读到 0
→ 知道客户端发送方向结束
→ 处理请求
→ send 回复


============================================================
10. shutdown(SHUT_WR) 和 FIN
============================================================

调用：

shutdown(
    sockfd,
    SHUT_WR
);

程序告诉内核：

“这条 TCP 连接的本端发送方向结束。”

然后由：

内核 TCP 状态机

负责协议层关闭流程，
通常会发送 FIN。

对端：

先把 FIN 前已有数据读完。

然后：

recv()
→ 0

所以：

shutdown(SHUT_WR)

和昨天学的：

recv() == 0

正好对应起来。


============================================================
11. close() 和 shutdown() 区别
============================================================

close(fd)

→ 当前进程不再使用这个 fd

通常理解：

“这个 socket fd 整体不用了”


shutdown(fd, SHUT_WR)

→ 只关闭发送方向


shutdown(fd, SHUT_RD)

→ 只关闭接收方向


shutdown(fd, SHUT_RDWR)

→ 两个通信方向都关闭


但：

shutdown()
≠
释放 fd

所以即使：

shutdown(
    fd,
    SHUT_RDWR
);

如果程序不再使用这个 fd，
最后仍通常需要：

close(fd);


============================================================
12. 一个完整半关闭例子
============================================================

客户端：

send(
    sockfd,
    "hello",
    5,
    0
);

shutdown(
    sockfd,
    SHUT_WR
);

char buf[128];

ssize_t n = recv(
    sockfd,
    buf,
    sizeof(buf) - 1,
    0
);

if (n > 0)
{
    buf[n] = '\0';

    printf(
        "server: %s\n",
        buf
    );
}

close(sockfd);

执行链：

send
→ 数据发完

shutdown(SHUT_WR)
→ 我不再发送
→ 内核处理 FIN

recv
→ 还能继续收服务器回复

close
→ 最终释放 fd
